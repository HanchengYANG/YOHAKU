## 用户定下的规则

- 界面文案简短，不显示用户不需要的技术细节。
- 出错只给错误代码，后台按代码查 `error_log`；管理员看到「提示 + 代码」。
- 保留现有视觉风格，只整理细节。手机主要用来拍照，电脑用来浏览和阅读。
- 必要时提交。用户嫌第 2 步太慢，已确认提速（2026-11-06）：每个任务只跑相关测试；每步结束跑一次 `npm run test:all`；小的视觉调整直接改，在浏览器里确认。用户不在时由 Claude 自行判断，不要停下来等确认。

## 遗留问题

1. `client/App.jsx` 顶部错误横幅仍显示服务器原文，留到第 3 步改用 `ErrorNotice`。
2. 添加页（统一导入）的说明文案仍然啰嗦，留到第 4 步。
3. 账号菜单「安装为 App」留到第 5 步。
4. 换机器后用真实数据再走查一遍：分页文章翻到第 2 页，回首页应显示「第 2 / M 页」，点「继续阅读」从第 2 页开始。

第 2 步整体审查中未修的小问题（重要问题和页面闪烁已修）：

5. **进度条提前到 100%**：`pageCount` 只统计已准备好的页（`server/sources.mjs` 的 `pageCounts`），正文还在准备时首页会显示「第 2 / 2 页」、进度条满格。应在准备完成前只显示「第 N 页」（`client/library-model.mjs` 的 `pageProgress`）。
6. **书籍页可能出现两条提示**：重命名或调整顺序失败后会重新拉取书籍，如果这次也失败（断网、或书已在别处删除），`App.jsx` 会把服务器原文放进顶部横幅，和书籍页的 `ErrorNotice` 同时出现。改横幅时（第 3 步）一起处理。
7. **手机首页 Tab 顺序**：`welcome.css` 用 `order` 把待处理条排在「继续阅读」前面，但 DOM 和 Tab 顺序仍在后面，应直接调整 DOM 顺序。侧栏只有「任务」设置了 `aria-current`，当前打开的书或文章没有。
8. **死代码**：`App.jsx` 的 `importText` 状态、`openUnifiedImport(text)` 参数和 `UnifiedImport` 的 `initialText` 已经不会是真值；`BookNavigation` 的 `onAddImage` 属性和「导入阅读资料」标签与实际的「添加文章」不一致。
9. **文案**：最近阅读里没打开过的文章也写「继续阅读：…」（`Welcome.jsx`）；任务页还有「导入资料」按钮，应改成「添加」。
10. **缺少浏览器测试**：侧栏任务数字、「N 个导入需要你处理 · 查看」、书籍页「需要处理／准备中」都没有能通过的浏览器测试；`stage1.spec.mjs` 有一个用例假设没打开过的文章能排进最近阅读前 6，前面的用例留下的数据多了会失败。
