# 余白 UI／UX 改版设计

日期：2026-11-06。分五步执行，每步自带测试、浏览器验证和提交。

## 已确认的前提

- **整体改版，先地基后页面**：第 1 步建立错误代码与错误记录，之后按导航 → 阅读 → 导入 → 任务／校对／设置逐组改页面。
- **视觉风格保留**：米色纸感背景、深绿侧栏、赭橙点缀、衬线标题不变；顺手统一按钮层级、间距和字号。
- **设备分工**：手机主要用来拍照导入，电脑用来浏览和阅读。阅读页以桌面为准，导入以手机为准。
- **文案精简**：用户不需要知道的技术细节一律不显示。
- **错误只给代码**：系统错误界面上只显示短代码，完整细节留在服务器，管理员在「错误记录」页按代码查找。

## 1. 地基：文案原则与错误代码

### 1.1 文案原则

- 页面最多一个标题加一行说明，或不写。说明只保留“不写用户就会做错”的内容，例如「PNG／JPEG／WebP，单张最大 12 MB」。
- 普通界面不出现提供方、模型 id、token 数、HTTP 状态码、处理编号、「分句」「注音角色」等内部术语。提供方和模型只出现在管理员的 AI 页。
- 状态写结果，不写过程：「正在准备」「可以阅读」「需要处理」，不写「分句尚未完成」「注音 2/5 步」。
- 按钮用短动宾：「开始阅读」「添加图片」「重试」。

### 1.2 两类错误

| 类型 | 例子 | 界面 | 记录 |
| --- | --- | --- | --- |
| 用户能自己解决 | 文件过大、密码错误、名称重复、版本冲突需刷新 | 一句白话，无代码 | 不写入 `error_log` |
| 其余所有错误 | 服务端异常、AI 调用失败、后台任务失败、对话中断 | 「出错了，请重试 · 错误代码 7K2QD9」，代码可一键复制 | 写入 `error_log` |

判定规则：带 `expose` 的 4xx 且属于输入校验、权限、冲突的错误归第一类；其余（5xx、AI 与提供方错误、后台步骤失败、流式对话失败）归第二类。

**AI 连接失效**（授权过期、API key 无效、`AI_AUTH_REQUIRED` 一类）是第二类中的例外：

- 管理员看到「AI 连接已失效 · 去 AI 设置」，链接直达 AI 页；
- 其他账号看到「AI 暂时不可用 · 7K2QD9」。

**断网或服务未响应**（`fetch` 抛出 `TypeError`）显示「连不上服务器，请稍后重试」。这类请求服务器没有收到，因此不给代码。

### 1.3 服务器：`error_log`

新表 `error_log`：

| 列 | 说明 |
| --- | --- |
| `code` | 主键，6 位 Crockford Base32（不含 I、L、O、U），如 `7K2QD9` |
| `created_at` | ISO 时间 |
| `user_id` | 触发的网站账号，可空 |
| `scope` | `http`、`task`、`source`、`import`、`chat` |
| `location` | 路由或任务步骤，例如 `POST /api/ai/chat`、`source:segmentation` |
| `kind` | 内部错误码，例如 `AI_AUTH_REQUIRED`，可空 |
| `status` | HTTP 状态，可空 |
| `message` | 原始错误信息 |
| `stack` | 堆栈，可空 |
| `context_json` | 文章／任务／来源 id、提供方、模型，以及 `sanitizeDiagnostic` 已有的诊断字段 |

- 统一入口 `recordError(error, context)` 返回代码。Express 错误中间件（`server/app.mjs`）、后台任务失败路径（图片任务、来源步骤、PDF 分章、文件解析）和流式对话失败都调用它。
- 每次启动及每天清理一次 90 天前的记录。
- 管理员接口：`GET /api/admin/errors`（倒序分页，可按代码搜索）、`GET /api/admin/errors/:code`。非管理员返回 403。

### 1.4 返回给前端的形状

- HTTP 错误：`{ error: "<一句白话>", errorCode?: "7K2QD9", action?: "ai-settings" }`。第二类错误的 `error` 统一为通用句，不带原始信息。
- 后台任务、来源步骤、导入草稿、对话的 `lastError` 一类字段改为只给 `errorCode`（加可选 `action`），原始信息只进 `error_log`。
- 本次改版前已保存的失败记录没有代码，界面显示「处理失败」。
- 执行详情（提供方、模型、推理强度、token）不再随普通响应下发到界面。数据库里保留，失败时写进 `error_log.context_json`。

### 1.5 前端

- 新组件 `ErrorNotice`：一句话 + 可复制的代码 + 可选操作按钮，替换现在直接显示原始错误的 15 处以上的位置（`ImageTasks.jsx`、`PagedReader.jsx`、`DocumentChat.jsx`、`Editor.jsx`、`UnifiedImport.jsx`、`SourceCorrection.jsx`、`ReadingPreparation.jsx`、`Reader.jsx`、`BookView.jsx`、`ImageImport.jsx`、`App.jsx`、AI 设置与角色配置页等）。
- `client/api.mjs` 统一处理网络失败，抛出带白话信息的错误，不再让「Failed to fetch」出现在界面。
- 删除 `ExecutionDetails.mjs` 与 `PagedReader.jsx` 中 `DiagnosticFacts` 的界面展示。

### 1.6 管理员「错误记录」页

- 入口在账号菜单，仅管理员可见。
- 列表倒序：时间、代码、账号、位置、一行摘要。顶部搜索框粘贴代码可直接定位。
- 点开展开完整信息、堆栈和上下文。

## 2. 导航、首页、书籍页

### 2.1 侧栏

- 顶部只留「＋ 添加」和「任务」（带待处理数字）。照片、文件、粘贴文字都在添加页内选择；「新建书籍」改为书架标题旁的「＋」。
- 底部只留账号行，点开菜单：AI（管理员）、错误记录（管理员）、邀请朋友（管理员）、安装为 App（桌面且未安装时）、退出。
- 手机侧栏结构相同。

### 2.2 首页

- 去掉统计栏。
- 第一块「继续阅读」：最近打开的文章、所在书籍、「第 N / M 页」、进度条和「继续阅读」按钮。从未读过任何文章时，显示最近添加的一篇。
- 有需要用户动作的任务时，显示一条「N 个导入需要你处理 · 查看」。
- 「最近阅读」按最近打开时间排序。
- 手机首页第一个动作是「📷 拍照添加」，其次是待处理与继续阅读。

### 2.3 书籍页

- 标题、「N 篇 · X 字」、主按钮「继续阅读 · <文章名>」（没有进度时为「开始阅读」）、次按钮「＋ 添加文章」（打开添加页并预选本书）。
- 重命名、调整顺序、删除书籍收进标题旁「⋯」菜单。书名输入框只在重命名时出现。
- 文章行只显示一种状态：「读到第 N 页」「准备中」「需要处理」，无状态时只显示字数。

### 2.4 阅读进度

- 新表 `reading_positions(user_id, document_id, page_index, updated_at)`，主键 `(user_id, document_id)`。
- 阅读页翻页时写入（防抖）；打开文章时恢复到记录的页。
- 首页「继续阅读」和「最近阅读」排序、书籍页「读到第 N 页」都读这张表。书籍的最近时间取其文章的最大值。

## 3. 阅读页（以桌面为准）

### 3.1 一条细栏

- 左：「← 书名」，独立文章为「← 书架」。
- 中：文章标题 +「N / M 页 ▾」，点开目录浮层，列出本书各篇及当前篇各页，可直接跳转。
- 右：注音开关、字号（点开滑杆）、校对、对话（带问答数）。
- 去掉：两组上一篇／下一篇、上一页／下一页的重复导航，「导入阅读资料」，「N 处注音 · 已保存」，篇选择下拉。

### 3.2 翻页

- 正文底部：「← 上一页 · N / M · 下一页 →」；键盘 ← → 翻页。
- 文章最后一页底部显示「下一篇：<标题> →」。

### 3.3 布局

- 进入阅读页时侧栏自动收起，栏左侧可一键展开（浮层）；其他页面保持用户的收起选择。
- 正文列定宽居中。
- 窗口足够宽时对话面板在右侧并排；不够宽（正文会小于定宽）时对话面板以抽屉覆盖在正文上方。
- 手机阅读页使用同一条细栏，对话保留底部面板。

### 3.4 划词提问

- 浮层按钮改为明确的胶囊按钮：「翻译」「讲解语法」「提问…」。
- 浮层优先出现在选区上方，避免盖住所问句子。
- 修正：文章首个标题不再与第一句一起被高亮为同一句。

### 3.5 准备未完成或失败时仍可阅读

- 基于已有的「准备期间预览已提取正文」（`PagedReader.jsx` 的 `provisionalPreview`），扩展到失败状态和旧文章（`Reader.jsx` 分句路径）。
- 始终显示原文；没有注音和划词提问。
- 顶部一行提示：「注音还在准备」或「准备失败 · 重试 · 7K2QD9」（AI 连接失效时按 1.2 的例外显示）。

## 4. 导入（手机以拍照为主）

### 4.1 手机拍照

- 首页「拍照添加」直接打开相机（`accept="image/*" capture="environment"`）；添加页另有「相册」。
- 每张照片自动上传（沿用现有草稿上传），以带序号的缩略图显示；长按拖动排序，点开可旋转或删除。
- 底部固定栏：「📷 拍下一页」「相册」，下方「完成 · N 张」。
- 「放进」默认上次所在书籍，可改为新文章或新书籍。
- 标题可空，默认「<月日> · 照片」，之后可改。
- 拍照来源类型默认为「照片」，不再出现单独的「确认来源类型」步骤；类型以右上角小标签显示，可改。
- 提交后进入确认页：「已添加，正在识别」+「再拍一篇」「查看进度」。导入后自动开始准备第一页，使电脑打开时已可阅读；实现时先确认现有行为，缺少则补上。

### 4.2 桌面统一入口

- 「＋ 添加」页：拖入或选择文件，或切到「粘贴文字」。
- 本地猜测类型；只有拿不准时（扫描 PDF／文字 PDF 等）才让用户选一次。
- PDF／EPUB 分章流程功能不变，文案压缩到最少，例如长段 OCR 与角色说明改为一个「AI 提议章节」按钮。

### 4.3 草稿与跨设备

- 未完成草稿出现在「任务」和首页「需要处理」。跨设备继续上传保持现状。

## 5. 任务、校对、设置与杂项

### 5.1 任务页

- 名称改为「任务」。单一列表：「需要处理」（失败、待确认、未完成草稿）在上，「进行中」在下；「已归档」为独立标签。
- 每行：标题、一句状态、一个主操作（继续／重试／查看）。不显示执行详情。
- 空状态只写「没有任务」。

### 5.2 校对页（`Editor.jsx`、`SourceCorrection.jsx`）

- 左正文、右原件的布局保留；原件栏加宽到约一半，缩放与旋转改为原图上的图标。
- 去掉说明段落与「注音来源：OpenAI · 模型」。处理状态合并为一个标签，例如「待核对」。
- 顶部只留标题、来源选择、「完成核对」「返回阅读」。

### 5.3 AI 页（管理员）

- 「AI 设置」与「角色配置」合并为一个「AI」页，两个标签：「连接」「角色」。
- 每个角色一行：名称、一句用途（约 12 字以内）、提供方、模型（只显示名称，不显示「名称 · id」）。高级设置默认折叠；去掉各角色下的长说明。

### 5.4 安装横幅

- 桌面不再弹出，入口移到账号菜单「安装为 App」。
- 手机只提示一次；点「暂不」后不再出现。

## 验证与提交节奏

每一步：

1. 服务器改动（错误记录、错误代码、阅读进度）先写 `node --test` 单元测试。
2. 更新受影响的 Playwright 用例；现有用例中断言旧文案的部分随新文案调整，不删除断言覆盖的行为。
3. `npm test` 与相关浏览器用例通过。
4. 在内置浏览器中按桌面（1280、800 宽）和手机（375 宽）走一遍受影响页面并截图。
5. 单独提交。

执行顺序：

1. 地基：错误代码、`error_log`、`ErrorNotice`、错误记录页。
2. 导航、首页、书籍页与阅读进度。
3. 阅读页。
4. 导入（手机拍照）。
5. 任务、校对、AI 页与安装横幅。

## 不在本次范围

- 离线阅读、多语言界面。
- 上述五部分之外的新功能。
