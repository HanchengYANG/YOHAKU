## 后续计划

### 第三阶段：AI 问答、旁注与笔记本

本轮采用受控 HTML 统一保存正文、段落、句子边界、图片来源及问答标记，先完成多图校对与划词问答。以下为本轮已实现的范围与验收要求；本轮验证记录见“实施顺序与验收”之后。

#### 1. 书籍—文章结构与受控 HTML 正文

- 阅读侧采用“书籍 → 文章”；独立文章可以不归入书籍。目录、数量统计、上一篇／下一篇均以文章为单位。
- 沿用现有 `documents` 作为文章记录，一篇文章可关联多张来源照片及各自的识别记录。正文以受控 HTML 为统一结构，连续阅读，不按照片分页；纯文本、搜索内容、hash 和导出内容从该结构派生。
- 使用标准 HTML 标签和明确的 `data-*` 属性：`p` 保存段落，`span` 标记具有稳定 ID 的句子和来源图片，`mark` 引用问答组 ID，`ruby`／`rt`／`rp` 保留振假名。保存时执行结构校验及 HTML 清洗，并校验引用的图片、问答组属于当前账号和文章。
- 对话内容仍独立保存在服务端，HTML 只引用问答组 ID。来源图片通过 `data-source-image-id` 标记，编辑时随对应文字节点保留；手动新增内容可以没有图片来源，不调用 LLM 推测。
- 图片识别后可选择“新建文章”或“追加到已有文章”。追加到同一篇的文字按顺序进入正文，阅读和提问不再受来源照片的分页限制。
- 编辑器受控维护这些结构和标记。选择正文位置时显示对应来源图，选择图片时定位并高亮对应文字节点；保留缩放、旋转及图片方向保存。本轮只定位到来源图片，不做图片内文字框定位。
- 同一段落可以包含多个句子，同一句子可以包含多个来源图片的文字；跨句或跨来源的问答标记可拆成多个具有同一问答组 ID 的节点。
- 同一照片混入其他文章时，由用户校对删改；OCR 继续负责正文识别和注音。
- 保留现有资料、ID、振假名和讨论记录，旧书页先作为独立文章保留，不自动判断或合并文章边界。旧单图文章转换时给对应正文节点添加该图片来源。

结构示例（对话内容通过 `qa-1` 单独读取）：

```html
<p data-paragraph-id="p1">
  <span data-sentence-id="s1"><span data-source-image-id="img-1">すべての日本人が名字を持つようになったのは，<mark data-qa-group-ids="qa-1">明治時代</mark>になってからです。</span></span><span data-sentence-id="s2"><span data-source-image-id="img-2">当時の政府が，すべての国民が名字を持つことを法律で決めました。</span></span>
</p>
```

#### 2. 保存句子边界，普通编辑不自动重新分句

- 首次 OCR 或文字导入时，让 LLM 对尚未分句的正文初始化句子边界，由程序写入 HTML 并分配稳定句子 ID。追加图片时保留已有句子结构，新增内容可接入末句或作为新句，再初始化未分句部分。
- 普通编辑直接修改句子节点中的文字，保留句子 ID、图片来源及问答标记，不因正文 hash 变化自动调用分句。在句子交界处，UI 明确让用户选择把新增文字插入前句或后句，并显示所属来源；手工新增来源可留空。
- 保留“重新分句”按钮，由用户显式触发 LLM 对当前正文重新分句。重分句只调整边界；程序保留原始文字、振假名、图片来源及问答组引用，跨新边界的同组标记可以拆成多个节点，不因此变成游离问答。
- LLM 只返回句子或意群划分，不负责生成来源、问答组 ID 或改写原文。服务端验证返回片段按顺序拼回原文，再应用新边界；失败保留现有正文、边界和标记，并提供重试。
- 从 HTML 中按明确的段落与换行规则提取纯文本，忽略注音和标记元数据，再计算 SHA-256 `bodyHash`；偏移统一使用 JavaScript UTF-16。初始化分句可按 hash 复用成功缓存，手动“重新分句”则重新请求模型。已有句子结构不被旧缓存自动覆盖，异步结果不覆盖请求发出后已被编辑的正文结构。

#### 3. 只做划词提问，一篇文章一条持久对话

- 本轮只实现划词提问，移除阅读页整篇文章的“问 AI”入口。首问和后续提问统一发送“所在句子 + 选中内容 + 问题”，不发送文章全文；跨句选区附上涉及的各句。偏移量和正文 hash 用于服务端定位、校验与记录，不要求模型根据偏移量寻找原文。
- 正文选中后，在选区附近提供“翻译”“解释语法”“自定义问题”，桌面和手机共用这一方式。划词本身不调用模型；快捷按钮直接发送对应问题，自定义问题输入后发送。
- 每个网站账号、每篇文章保留一条对话，直到用户手动删除；关闭面板、重开、切换选区、修改正文和手动重新分句都继续同一条对话，不存档、清空或重建。
- 每次从正文划词并实际发送提问时建立一个问答组；同组选区下的翻译、语法解释和继续追问关联到该组，新一轮划词提问建立新组。所有组仍属于同一篇文章的同一条对话。
- 服务端结构化记录每个问答组的文章、账号、对话和组标识，以及发送当时的句子 ID、选中原文、完整句子、起止偏移和正文 hash。当前位置关联由 HTML 中的问答组标记表达。选区提取排除振假名；服务端从对应句子节点读取正文，只校验本次引用，不要求历史引用继续存在于修改后的正文中。
- 每次问答记录操作类型（翻译／语法／自定义／追问）、实际发送的问题文本、AI 回复、使用的外部来源和时间，明确关联到对应问答组。正文变动后保留已记录的引用与句子，之后生成笔记可直接读取这些条目。
- 通过“对话记录”入口重开已有对话，支持查看、继续追问和手动删除。删除会话时同步清理对应正文问答标记。移除“新讨论”“选择已有讨论”和手动粘贴原句输入框，保留现有桌面侧栏、移动端底部面板。

| 操作 | 问题内容 | 发送方式 |
| --- | --- | --- |
| 翻译 | 结合所在句子翻译选中内容 | 一键发送，无需输入 |
| 解释语法 | 解释选中内容的语法及其在句中的作用 | 一键发送，无需输入 |
| 自定义问题 | 用户输入的问题 | 输入后发送 |

每次请求均带对应问答组的句子与选中内容，包括继续追问。组与组在界面和服务端记录中明确分开；模型仍延续同一条对话的历史，每轮明确当前讨论的选区，不将分组视为模型历史的自动隔离。只有用户手动删除文章对话后，下次提问才建立新对话。

打开面板本身不发起模型请求。正文 hash 用于初始化分句缓存和当次引用校验，不决定对话生命周期，也不触发编辑后的自动重分句。历史消息展示发送时保存的引用和句子，不按修改后的正文重新解释旧引用；本轮只保存问答资料，笔记、复习卡片生成留待后续。

#### 4. 正文中的问答标记与游离片段

- 阅读页面和正文编辑区都标出已关联问答组的选中片段，采用轻量下划线或旁侧标记；点击标记可查看对应问答组。标记不影响振假名显示、文字选择和编辑，同一位置关联多个组时可合并显示数量并选择查看。
- 编辑器保留和移动 HTML 中的问答标记，渲染时直接按标记定位，不用全文旧偏移推算当前位置。发送时保存的原文、句子和原始偏移记录保持不变；标记内文字被校正后仍可保留位置关联，同时提示原引用文字已修改。
- 删除某组全部正文标记会使该组游离，编辑区即时显示受影响的组及数量。不按相同词串自动关联到文章其他位置。
- 未保存的编辑可以撤销或取消，HTML 中的文字、句子边界、图片来源及问答标记一起恢复；保存时根据仍存在的标记同步关联／游离状态。重新分句保留问答组标记及原有对话。
- 已没有正文标记的组标为“游离／原文关联已删除”，保留其引用快照、问题、回复和来源，在对话记录中仍可查看和继续追问；追问使用该组保存的句子与选中内容。删除正文不删除对话，也不新建文章会话，后续生成笔记仍可使用这些资料。

#### 5. AI 问答支持联网

- 问答沿用当前 ChatGPT 订阅接入和网站共享授权，为问答启用实时网页搜索，并调整当前统一禁止联网的助教指令；OCR、注音与分句保持各自现有的文本／图片处理职责。
- 使用外部资料时提供可点击来源，回答中区分原文依据与检索到的背景信息。联网失败时明确反馈。
- 先在项目适配的 CLI 版本验证真实搜索事件与来源返回，再接入界面。配置依据见 [OpenAI Docs：Web search mode](https://learn.chatgpt.com/docs/config-file/config-basic#web-search-mode)，实时搜索对应 `web_search = "live"`。
