# 日语阅读与笔记网站：给本地 Codex 的需求与交接

整理日期：2026-10-28。本文可以直接作为接手项目的任务说明。

## 1. 我要做什么

请帮我实现并部署一个日语学习网站，主要供我个人使用，也可能给少量朋友使用。界面和 AI 讲解以中文为主，学习材料是日语文章、歌词和书籍。

我的问题是：阅读时查过生词、语法，也做过记录，但过一会儿又忘了。因此网站要把阅读、提问、笔记和后续复习串起来。笔记是核心功能。

主要操作流程：

导入照片、截图或文字 → 校对识别结果和注音 → 阅读、听朗读 → 选中文字问 AI → 继续追问 → 一键整理为笔记，放回原文旁边 → 以后带着原文语境复习。

项目之前暂称“余白 · 日语阅读与笔记”，这是工作名称，可以沿用，并非必须重新确认的前置条件。

## 2. 部署方向与费用约束

- 我已经决定改用本地 Codex 开发，并在自己的树莓派上部署；不必继续依赖 Sites。
- 我希望网站运行时的 AI 功能也尽量使用现有 ChatGPT／Codex 订阅额度。仅仅“用 Codex 写网站”，上线后却仍要求额外付费的模型 API，不符合我的意图。
- 不要自动创建 API key、开通付费服务，或默认为我接入按量收费的 OpenAI API。早先说过“费用先不用考虑”，后面已明确提出不想为 API 另付费，以后面的要求为准。
- 优先验证通过官方支持的 Codex CLI、SDK 或 app-server 接入方式实现运行时 AI 的可行性。具体接口、目标架构支持和认证方式由你检查当前官方文档并实测，不要照搬旧对话中的技术判断。
- 先验证图片输入、多轮对话、返回结构化识别结果和持续运行等关键能力。不要把“CLI 能启动”当作整个方案已经打通，也不要通过提取登录 token 来伪装成通用模型 API。
- OCR、解释、笔记整理和语音朗读分别需要验证。不要假定 Codex 订阅自动覆盖语音合成。若某一功能无法满足费用和质量要求，请具体说明，再与我确认替代方案。
- 不要求树莓派本地运行大型语言模型。先根据机器实际资源选择合适的应用架构。

## 3. 材料输入与识别

必须支持两类输入：

1. 手动输入或粘贴日语文字，包括文章和歌词。
2. 上传图片，包括清晰截图和手机拍摄的真实照片。

照片不能按“都是平整截图”来处理。需要考虑书页弯曲、拍摄角度、阴影、手指、背景、手写笔记，以及横排、竖排和双页展开的书籍。

识别结果应区分正文、原有振假名、页码等非正文内容，以及手写批注，避免把小号注音串进正文。双页和竖排要识别正确阅读顺序。

导入后应能对照原图校正正文、断句和注音；识别不确定的内容应允许人工确认。原图保留，便于以后回看和重新校对。不要把第一次 OCR 的输出直接当成无法修改的最终原文。

## 4. 注音是明确要求

这里的注音指日语振假名（ふりがな／ruby）。我要求两个方向都支持：

- 输入图片里本来就有的注音，要尽量识别出来，并对应到正确的汉字或词组上。
- 网站显示原文时，要显示这种日式注音格式。横排时小假名在汉字上方；若实现竖排显示，则放在相应字词右侧。不能只显示“汉字（假名）”，也不能只给出独立的假名转写段落。

实现时可以使用 HTML `ruby`／`rt`，重点是对应关系和排版正确：

- 允许按词或词组对应，不要求机械地给每个汉字分配一个读音。
- 例如「背中」可整体对应「せなか」；「生まれた」中的「う」应对应「生」，不要把送假名重复算入注音。
- 歌词、文学材料可能有作者指定的特殊读法。图片里已有的读音优先保留，不要被普通词典读音静默覆盖。
- 原文没有注音时可以补充生成，但要区分原有读音和后补读音，并允许修改。
- 校正过的读音需要在后续显示、保存和朗读中保持一致。

## 5. 阅读与朗读

- 支持舒适地阅读文章和歌词，保留段落与歌词分行。
- 需要日语朗读，目标是标准、自然，不能只做到“能发出声音”。
- 支持整篇、单句和选中片段朗读；提供暂停、重复和慢速等基本控制，能标示当前朗读的句子。
- 朗读要考虑上下文、多音词及我修正过的读音，尤其是歌词中的特殊读法。
- 语音方案必须拿真实日语材料听评。若使用浏览器自带声音，需要实际检查可用声音和效果，不能仅因语言标签是日语就宣称达到要求。
- 歌词的需求是朗读，不是合成演唱。

## 6. 选中文字问 AI，并整理成原文旁注

这是核心交互，请完整实现：

1. 我在原文中用鼠标选中一个词、一句或一段文字。
2. 选区附近快速出现“问 AI”按钮。右键菜单可作为补充，关键是不用手动复制粘贴到另一个页面。
3. AI 能结合选中文字和所在原文的上下文，解释意思、语法、生词、词形变化等；讲解主要用中文，并配适当的日语例句。
4. 我可以继续追问，形成围绕这一选区的多轮对话。
5. 对话之后点击“整理为旁注”或同等按钮，AI 把这段讨论整理成有条理的笔记。
6. 整理好的笔记插入对应原文边上，与原文选区保持关联；我可以继续编辑。

补充要求：

- 笔记编辑区域中选中文字时，也应方便地继续问 AI。
- 原文和笔记之间可以互相定位，例如点旁注时突出对应原句。
- 桌面适合旁边显示笔记；手机可以在对应句附近展开，不强求照搬桌面布局。
- 完整聊天记录应保留，后续能够继续讨论。整理成笔记不等于删除聊天记录。
- 原文被校正或编辑时，要考虑旁注锚点如何保持关联；无法自动对应时允许重新指定，避免笔记无声地挂到错误句子上。

## 7. 笔记本

- 支持我手动输入笔记，也支持 AI 生成后再修改。
- 能在原文旁边做笔记，也能在独立笔记本里查找和阅读笔记。
- 笔记保留来源文章和原句，能够回到原文，不要变成脱离上下文的一堆解释。
- 原文旁注和笔记本展示的是同一条笔记，修改应同步，不能复制成两份互不关联的内容。
- 支持标题、标签、搜索，以及逐渐追加例句和补充说明；语法笔记需要能长期积累。
- 数据要持久保存，刷新页面、换设备访问同一账户、重启服务后仍能使用。提供方便导出的方式，例如 Markdown 笔记和结构化备份。

## 8. 帮助记住，而不只是查过

围绕“过一会儿就忘记”这一问题，第一版可以采用简单的复习方案：

- 由我选择哪些词或笔记“想记住”，加入复习；不必把每次查询都强制做成卡片。
- 复习保留原句和来源，先尝试回忆，再展示解释。
- 根据“记住了／模糊／忘记了”等反馈安排下次复习。

先让阅读、提问、笔记、保存这条主流程真实可用，再完善复习。不需要复杂积分、排行榜或打卡体系。

- 学习内容需要有持久存储、备份与恢复办法；不能只存在浏览器内存或临时文件里。
