# 第二阶段：订阅授权、图片草稿、书籍与 AI 讨论

更新日期：2026-10-28。第一阶段已获用户验收；第二阶段主流程已实现，OCR＋注音按用户确认方案收口，整体体验仍待验收。旁注、笔记本、朗读、复习及树莓派部署尚未展开。

## 当前纯LLM两阶段流程

用户确定纯LLM方案，并要求在UI上合成一次操作：点击「识别并注音」后自动连续执行两个独立请求。第一阶段识图并校正明显OCR错误，只返回`{text}`，保留原文段落／歌词分行；第二阶段自动参考原图，只返回含汉字完整词的`{t,r}`列表，不重复输出纯假名、标点或正文。两步完成后才进入校对页，不在中间要求再次点击。程序按出现顺序定位词并原样补回间隙；所有汉字都必须覆盖，不确定读音也需返回null，避免重复词错位。错误、漏词或不匹配的结果拒绝应用，已有source／manual／generated保持。两个请求仍为low。

正常流程总时间从上传成功JSON解析完毕开始，到识别、注音及最终校对页原图metadata／解码／双rAF完成为止，显示「上传后识别与注音完成用时」。不把后端正文请求耗时称为中间正文页面时间。注音失败保留上传图片和已识别正文，「重试注音」只重做第二步；也可「先校对正文」进入草稿，随后再补音。重试沿用首次上传的计时起点，包含失败后人工等待，故不拿重试轮次作速度基准。换图会清空阶段缓存，处理期间禁止换图、重复提交和取消。完成草稿仍需人工校对并保存，才进入书架。

当前第一阶段排除图片小注音、页码和手写批注，只返回纯文字；程序按换行生成paragraph，sourcePage为unknown、nonBody为空，不生成标题／列表语义或原图方向／页边界元数据。历史结构化资料保留兼容。用户随后要求第二阶段也传原图参考：优先采用清晰印刷注音和特殊读法，无注音或看不清时按已确认正文语境推断，仍不确定留空。图片只供读音参考，不能据图改正文。新增读音仍统一标generated，不在没有逐词来源证据时一概标source；本次参考图片ID／revision与策略另存`annotation.imageReference`／`readingPolicy`。无缺失汉字时不读取图片、不发模型请求；推理期间图片版本变化则拒绝应用。图片读取、方向规范化及传输也计入独立注音页面时间。历史原注音资料和手动校对不迁移。食べる→たべる、生まれた→うまれた保持完整词校对，阅读时分别只在食／生上显示た／う。お父さん仍按整词校对，只在父上显示とう。纯假名不重复注音。

下文的本地OCR与原注音优先策略为此前实验记录，代码保留供回溯；当前导入界面已移除本地引擎选择。

两阶段API仍为`/images/:id/recognize`与`/images/:id/annotate`，由导入界面依次调用；正文与后续注音证据分别保存。下文较早的“同次纠错注音”及“单独按钮注音”仅为历史对照。

## 多页书籍与逐张追加

用户补充的整本书需求属于本阶段：书籍由多个有序页面组成，一张图片保存为一页。当前按「每次导入一张，保存到指定书籍」实现：

1. 从书架「新建书籍」，填写书籍名称；在目录中「添加图片页」或「添加文字页」。每次追加一页，图片仍按现有两阶段流程识别与校对。
2. 也可先正常导入图片或文字，在校对页「保存到书籍」选择已有书籍，或点击「新建书籍」后「创建并选中」。既有独立材料也可在校对时选书或新建后归入一本书，保留原材料ID及所有记录。保留独立材料选项，保存后进入对应页面阅读；已归书页面校对时不提供移动到其他书籍的选择。
3. 书内页面按顺序显示，阅读器有上一页、下一页和选页入口，可回书籍目录继续添加；目录支持编辑书名与调整页面顺序。
4. 各页独立保存原图、正文、整词读音、识别／注音证据及讨论。已有独立材料的「转为书籍」原地保留材料ID，作为第一页，不复制或清空已有讨论；书页不再散列到独立材料列表。

一个导入页面对应一次图片或文字导入；双页照片仍保留为同一张来源图，不自动切成两个页面。删除单页会同时删除该页讨论并重排其余页码；删除整本书会删除其所有页面与对应讨论，图片和识别草稿仍保留在本机数据中。

本轮多页书籍已完成开发验证，用户实际整本书体验仍待验收；验证范围单独记录，不用此前单图OCR实测替代整本书的保存、翻页和重开验证。

## 历史实验：NDLOCR-Lite 与独立注音

此前新增[日本国会图书馆NDLOCR-Lite](https://github.com/ndl-lab/ndlocr-lite)的CPU本地整页识别选项，面向图书、杂志，通过DEIMv2布局、PARSeq文字识别及读序模块处理整页；实际使用官方1.3.0、commit `e57f7c6bd9cfb3de5f12f008e71ad2122bd44bfd`，四个ONNX模型随Python包安装。启动网站前安装：

```bash
uv venv --python 3.11 .venv-ndlocr
uv pip install --python .venv-ndlocr/bin/python -r scripts/ndlocr-requirements.txt
```

自备Python可设置`NDLOCR_PYTHON`；默认从已安装包加载。`NDLOCR_LITE_DIR`只用于明确指定官方源码目录。第一次请求中加载模型，此后进程复用。实验中的加载、识别、纠正文及页面渲染均计入「上传后正文完成用时」，单独注音按点击到结果绘制完成计时；这些分段指标不代表当前一键流程的总用时。历史接口保留，当前导入界面不提供这个选项。

本地适配会排除明确分类为ルビ的区域，但分类错误或无法区分的小字仍保留并提示。初测对竖排和主要数字明显好于mokuro＋MangaOCR，仍有斜行错识、重复、注音混正文；没有声称逐字准确或厂商速度可直接外推。纯OCR报告位于`artifacts/ndlocr/report.json`，不等于页面等待时间。

NDL试验分支现默认在逐行识别前自动估计横排正文的倾角和曲率，紧裁并重采样原RGB像素。二值掩膜只用于估计几何，不用于替换识别图；不修改上传原图。可靠拉正且大字连通块至少25个的长行使用较宽的PARSeq-100输入。竖排、短行、拟合不可靠或超过OpenCV重采样尺寸限制时保留原裁图。每行处理／回退原因、耗时和识别器选择保存在`processing.localOcr.preprocessing`；这些工作也计入正文页面完成时间。`NDLOCR_PREPROCESS=0`只供同图基线对照。几何检查可用`.venv-ndlocr/bin/python tests/ocr-line-preprocess.test.py`运行。

本地纠错请求只发送已按本地顺序组织的文字，模型返回固定顺序的`texts`数组；标题、方向、来源页和草稿包装由程序补齐，原始OCR区域仍完整保存。不让文字纠错任务重复分析坐标或生成读音。注音提示也已缩短，仍由独立按钮触发，正文逐字校验和已有读音来源保护保持。

OCR提示词已从2806精简到1026字符，Schema及数据结构保持。OCR显式请求low，普通讨论保持原来的默认／线程配置；实际模型与等级写入识别记录。模型仍取本人账号目录默认图片模型，当前实测为gpt-6.1-sol；目录推荐等级是low，旧代码未传等级且服务返回null，不能将旧请求称为medium。

此前速度实验记录在`artifacts/ocr-speed-comparison/`：小截图旧配置17.2秒、首版短提示18.9秒；整页教材旧配置62.9秒，最终短提示＋low为46.7秒。这些仅为CLI请求耗时，每配置单次、启动状态不同，不代表完整页面等待时间。数字原注音在精简初版出现覆盖减少，最终版本已修正并确认保留。用户随后要求比较MangaOCR分步流程，计时改为上传完毕到校对页面完整可用，见下文。

## 历史实验：本地 MangaOCR

MangaOCR选项保留作对照：mokuro 的 comic-text-detector 自动找文字区域，`manga-ocr` 本地识别，再调用已有订阅连接按文字上下文只纠正文。没有人工预裁图，也不把原图发给纠错LLM。注音由独立按钮执行，新增读音标为generated。原始本地OCR、自动区域坐标、冷启动信息和阶段耗时保存在识别记录的processing字段。

纠错与注音各自显式请求`low`，这是当前模型目录支持的最低档；不支持时拒绝请求，不静默升档。纠错仅返回`texts`，完全不含读音；注音独立Schema用`t/r`短字段，只处理没有读音的文字跨度。程序严格核对原文、数量和字段，再补回generated来源，不改变保存结构。

这里实际使用pip包 `manga-ocr`（kha-white/manga-ocr，权重kha-white/manga-ocr-base），不是最初链接的gnurt2041轻量模型；后者公开仓库未提供训练后权重。保留的实验接口需要单独安装本地依赖；当前导入界面没有此选项：

```bash
uv venv --python 3.11 .venv-mangaocr
uv pip install --python .venv-mangaocr/bin/python 'torch==2.15.0+cpu' 'torchvision==0.29.2+cpu' --index-url https://download.pytorch.org/whl/cpu
uv pip install --python .venv-mangaocr/bin/python -r scripts/manga-ocr-requirements.txt
```

也可以在Python虚拟环境中用pip执行同样安装。自备环境可设置`MANGA_OCR_PYTHON`。首次需联网下载两个上游模型，之后本地工作进程按需加载并保持在内存，退出网站时关闭；加载若发生在识别请求中，也算入页面等待时间。安装失败或本地识别失败会显示错误，不用伪造结果替代。

实验的正文指标从浏览器确认上传成功、读取完上传响应开始，到正文草稿返回、原图metadata就绪、当前版本原图解码完成，并经过页面绘制后结束。校对页显示「上传后正文完成用时」。它包含本地检测／OCR、请求中的模型加载、LLM正文纠错、结果校验和保存、网络传输及页面显示；独立注音另从按钮点击到该次结果绘制完成计时，不含中间人工等待。不能将未注音的正文指标直接与旧版已含注音的完整指标比较。`serverMs`和模型内部耗时只作排查参考，不能代替页面指标。

本地模型可能漏检测、混入小注音或产生错误句子，文字LLM无法可靠恢复漏失的原文、原图特殊读音或专名。检测不到区域时整图尝试会明确提示。识别期间若另一窗口旋转原图，本次草稿拒绝保存并要求按新方向重试。两种方式均先进入可编辑草稿，不自动写入书架。

人工校对已支持按词查找所有位置、全选或勾选部分位置，再显式批量应用读音。例如全篇名字都设为みょうじ，或分别选出读みょうじ和ミンツー的两组。人工明确全选时允许全文修改；AI不会在没有人工操作时擅自统一全文同词。这项范围控制已完成真实网页保存与刷新核对，第二阶段仍待用户体验反馈。

按用户反馈完成以下开发验证，等待用户体验验收：

- 聚焦注音校对项时，全文中的对应出现位置高亮；批量查找在全文直接点选，支持全选与部分选择。
- 阅读与编辑结果统一横排；来源原文的横／竖方向另存为信息。
- 原文保留、横排与结构兼容：当前正文转写不改写原文，可校正明显OCR识别错误并合并物理折行；历史heading／list_item／paragraph层次继续渲染和保存，当前新导入只生成paragraph。
- 旋转后保存应用内照片，同一图片ID之后返回转正的像素，重开无需再次旋转；保存动作带版本核验，内部保留旧像素版本以防保存失败损坏图片。

## 当前入口

打开 <http://127.0.0.1:4317>，先创建站内账号或登录。首次创建的账号接收旧本机资料；朋友需要邀请码注册，书架与授权相互独立。

1. AI 设置：初始用户可点击「绑定刚才的 ChatGPT 授权」认领此前已完成的授权；其他用户点击 **Continue with ChatGPT**，在官方页面授权自己的订阅。不会借用别人的连接。
2. 图片为主要输入：选择、粘贴或拖入 PNG、JPEG 或 WebP（最大 12 MB），点击一次「识别并注音」，先识别／纠正正文，再参考原图生成缺失读音，两步完成后进入校对草稿。新增读音为generated；历史source与人工manual继续区分。注音失败可只重试注音，或先校对已识别正文。桌面正文与原图并排，支持高亮联动、全文点选范围和批量改音。原图可旋转与放大；放大只调整显示，旋转可通过「保存图片方向」或「保存并阅读」写回应用内照片。当前纯文字方案不返回单独的非正文记录；旧资料的非正文仍默认收起。点击「保存并阅读」后才写入书架。
3. 书籍：先建书再添加图片页／文字页，或导入校对时选择「保存到书籍」。每次一张，各页分别保存，在目录与阅读器中按序切换。
4. AI 讨论：在已保存材料中点击「问 AI」，可填原文片段或围绕全文提问、继续追问，讨论可重新打开。选区附近快捷提问和对话转旁注属于第三阶段。

没有取得授权时会如实提示，不返回演示识别或伪造答案。授权成功也只表示订阅权限已批准，仍需真实推理完成来验证模型访问。

## 认证与数据

- 使用官方 SIWC 动态注册、PKCE、state、nonce、ID token 签名／issuer／audience／时效与授权 scope 校验。
- 应用自己获取的凭据位于 `data/users/<userId>/providers/openai/`，目录 0700、文件 0600、原子写入；不读取或复制现有 Codex 登录文件，不创建 API key，不自动切换到额外收费 API。
- Codex app-server 用 stdio 连接；模型目录仅用于选取支持图片的模型，不能作为账户推理权限证明。只有最终 `turn.status=completed` 且完整最终文本可用才算成功。
- 网站账号、资料、授权目录和聊天线程均隔离。OpenAI 的同一身份不能同时绑定到不同网站账号；未登录请求被拒绝，朋友未授权时不会触发管理员的模型调用。当前服务仍只绑定本机地址。
- 原图在 `data/images/`；识别草稿、原图引用、注音来源、阅读顺序与非正文记录持久保存。原文／读音均可手动修改。
- 数据库采用增加字段的迁移方式，原文保持。迁移前备份位于 `data/backups/before-stage-2.sqlite` 和 `before-accounts.sqlite`，不进入 Git。
- Provider 接口独立于图片／讨论业务。当前仅 OpenAI 启用；Claude、API Base 是禁用的空预留，不会联网或创建密钥。详见 [架构说明](architecture.md)。

## 独立CLI验证与真实网页证据

当前`verify:ai`脚本仍调用历史`OCR_PROMPT`／`OCR_SCHEMA`，用于结构化识别、source／generated来源与续聊诊断，输出到image-first-context-fallback子目录。它没有走当前正文→注音的两个HTTP请求，不能作为一键导入的验证命令；当前真实一键证据为高清23，见[实测记录](validation-2026-10-28.md)。下述07／06及原有网页材料均按历史策略分别保留。

此前Chrome扩展未连接时，另用独立CLI直接调用本人绑定provider实测07清晰注音截图与06无注音样本：07三处读音为source，显示父→とう、歳→さい，整词お父さん保留；但眞仍被误识为真，不能称为正文逐字通过。06正文六行93字、24组generated，食べる和生まれた保持整词，没有纯假名冗余注音。结果在 `artifacts/ruby-policy-live/`，不写入或覆盖书架材料。截图 `artifacts/stage2-kanji-only-display-desktop.png` 是隔离真实界面的手工注音材料，不能当作真实OCR截图。

```bash
npm run verify:ai
# 在全新 CLI 进程中恢复同一个线程：
npm run verify:ai -- --resume
```

脚本直接调用当前网站用户绑定的 provider，默认选择初始用户；可用 `--user=用户名` 明确选择。为避免与网站并发刷新旋转凭据，运行时需要先停止本机服务。未建站内账号或未绑定授权时退出，不发起推理。绑定完成后才会：

- 直接测试中文解释与连续追问，并以随机讨论代号验证上下文，不在书架创建或删除材料。
- 分别真实识别三张原始测试图和一张新生成的日语文字图，检查关键正文、生成读音、手写批注分离与双页顺序；同词异读和完整词形还需人工对照。
- 把该历史结构化策略的结果保存到 `artifacts/ai-verification/<userId>/image-first-context-fallback/`，旧ai-context报告保持独立；用新的CLI进程恢复同一线程并验证讨论代号，运行结束后重开网站服务。

自动核对点只证明被检查的部分；正文和上下文读音的准确性不能靠少数核对点推断。真实 OCR 完成后还需逐图对照，发现问题应记录，不能硬编码修正固定样本。
