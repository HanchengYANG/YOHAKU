# 余白 · 日语阅读与笔记

面向个人使用的日语阅读与笔记工具。第一阶段的阅读、保存与振假名校对已验收；第二阶段已实测个人订阅连接、真实模型识别、网页图片校对保存与网页讨论。照片与截图是主要输入，支持选图、截图粘贴、图片方向保存、原文联动高亮与全文点选批量注音。书籍按多个页面组织，每次导入一张图片并保存到指定书籍；第二阶段整体体验仍待用户验收。

每个网站账号单独绑定自己的 AI 授权；朋友通过邀请码注册。OpenAI 是目前唯一实现的 provider，Claude 和 API Base 保持空预留。边界与目录见 [架构说明](docs/architecture.md)。

首页提供真实书架统计和最近阅读入口，使用深色书架、暖色纸面与两张阅读配图；素材与生成提示词见[图片说明](docs/design-assets.md)。图片上传显示实际发送进度，正文识别、注音和AI回答显示当前阶段与已用时间，等待较久时补充状态说明。模型处理阶段使用活动进度条。

新图片点击一次「识别并注音」，自动连续完成两个LLM阶段：先识别并校正正文，再参考原图清晰的印刷注音和正文语境生成含汉字完整词的假名，完成后进入校对页。后端仍分别处理，不重复生成整篇正文，也不改动已识别正文。注音失败可只重试注音，或先校对已完成正文。新增读音统一标为generated（AI生成，可参考原图），不确定时留空，已有读音和来源保持。读音按完整词保存和校对，阅读时只在汉字部分显示，假名不重复注音。例如お父さん仍按整词校对，显示为父上方的とう；食べる显示为食上方的た。人工可查找同词并全选或点选部分位置批量修改，旧资料不自动改写。

书籍包含按顺序排列的多个页面，每次导入保存为一页。可先「新建书籍」再逐次添加图片页／文字页，也可在导入校对时用「保存到书籍」选择已有书籍或新建一本。各页分别保留正文、注音、原图、识别记录和讨论，阅读时支持上一页、下一页和选页；书架同时列出书籍与独立材料，书内页面不重复散列。既有独立材料可「转为书籍」作为第一页，也可在校对时选书归入，保留原有内容和讨论。

横排和竖排来源均输出横排阅读。AI按原图读序转写正文、校正明显OCR识别错误并保留段落／歌词分行，不改写原文字词、标点或专名；识别草稿仍需对照原图校对。

## 本机运行

需要 Node.js 24（包含 SQLite）。

```bash
npm ci
npm run dev
```

开发页面：<http://127.0.0.1:5173>。API 默认监听 `127.0.0.1:4317`。

构建后运行：

```bash
npm run build
npm start
```

打开 <http://127.0.0.1:4317>。当前绑定本机地址；公网入口和树莓派部署留在后续阶段。

## 文件结构

| 目录 | 用途 |
| --- | --- |
| `client/` | 阅读界面及样式 |
| `server/` | HTTP API 和 SQLite 存储 |
| `server/providers/` | 隔离于业务层的 AI 提供方及其认证／运行时实现 |
| `shared/` | 正文与振假名数据处理 |
| `tests/` | 数据、接口和浏览器验证 |
| `scripts/` | 开发与维护命令 |
| `docs/` | 原始需求、阶段计划和验收说明 |
| `fixtures/images/` | [统一测试图片集（原有样本、注音参考及追加照片）](fixtures/README.md) |
| `data/` | 本地数据库，自动生成，不进入 Git |
| `artifacts/` | 本机测试产物，不进入 Git |
| `archive/` | 原始交接压缩包，不重复提交 Git |

`docs/requirements.md` 保留原始交接内容，内文中的 `test-images/` 现对应 `fixtures/images/`。
