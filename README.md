# YOHAKU

**给喜欢的日语，留一点余白。**

YOHAKU（余白／よはく）是一个面向个人使用的日语阅读与学习工具。把书页照片、截图、歌词或文章放进自己的书架，借助 AI 识别正文、补全振假名，再对照原图校对、阅读和提问。

从一段想读的日语开始，一页一页积累自己的阅读材料。

## 可以做什么

- **导入图片和文字**：选择、粘贴或拖入照片与截图，也可以直接粘贴日语原文，保留段落和歌词分行。
- **后台识别、注音与分句**：图片上传完成后，一键提交任务，后台逐张识别正文、参考原图生成读音，再对整批正文统一分句。三阶段全部完成才进入待校对。任务页显示步骤、张数与已用时间；锁屏、刷新或关闭页面后继续执行，同账号换设备可查看进度和结果。
- **跨设备接着上传**：选图后自动上传并保存导入草稿。A 设备传完一张后可退出，B 设备从「任务与导入草稿」继续添加图片、排序并提交；尚未传完的本地文件可重新选择或移除。任务以日期时间、书籍／标题或原文件名及短编号区分，有未完成事项时才显示首页和侧栏入口。
- **对照原图校对**：编辑正文与整词读音，联动高亮对应位置；按词查找后，全选或点选部分位置批量改音。支持原图放大、旋转及保存方向。
- **专注日语阅读**：振假名显示在汉字上方，可切换注音、调整字号。桌面书架可收起并记住选择，对话关闭后正文利用剩余宽度。读音按完整词保存，显示时避免给正文中的假名重复注音。
- **整理书籍与文章**：保存独立文章，或归入书籍；支持搜索、文章排序与上一篇／下一篇。一篇文章可追加多张照片，来源图、识别记录和正文位置互相对应。任务结果先进入待校对草稿，手动保存后才创建或追加文章；识别失败可对照原图手动录入，注音失败可手动补音或先保存正文。
- **划词问 AI**：选中原文即可翻译、解释语法或自定义提问；每轮只发送选区及所在句子，可联网核实并显示来源。一篇文章保留一条对话，按选区分组，编辑与重新分句后继续保留；删除原文关联的问答仍可查看、追问。

## 开始使用

### 环境

- **Node.js 24**，项目使用 Node 内置 SQLite；`.nvmrc` 指定 `24.14.0`。
- AI 可使用 **ChatGPT 订阅授权**，或连接 **iliad codix**。
- 使用 ChatGPT 订阅时需要 **Codex CLI**，当前运行时适配 CLI `0.160.1` 和 `0.163.0`，其他版本会拒绝启动 AI 请求；可通过 `YOHAKU_CODEX_PATH` 指定可执行文件。iliad codix 使用服务方的 API key，无需 Codex CLI 或 OpenCode。

### 本地开发

在项目根目录执行：

```bash
npm ci
npm run dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。前端由 Vite 提供，API 默认运行在 `127.0.0.1:4317`。`npm run dev` 会读取根目录的 `.env`（模板见 `.env.example`，命令行变量优先），局域网、HTTPS 等配置写进去后无需额外参数。

### 在手机上访问开发环境

手机通过局域网访问时需要 HTTPS，Service Worker 和 PWA 安装都依赖它。直接执行：

```bash
npm run dev:https
```

脚本会自动探测本机局域网 IP、按需调用 `scripts/dev-tls.sh` 在 `~/.local/share/yohaku/dev/` 生成（或在 IP 变更时更新）自签证书，并启动 HTTPS 开发环境。若希望日常 `npm run dev` 默认启用，可 `cp .env.example .env` 并取消注释其中的局域网一节（`HOST=lan` 与 `TLS_*`）。

然后在手机上信任这张证书。第一次打开地址时浏览器会提示连接不安全，选择继续访问；页面底部会出现「下载证书」按钮。证书也可以直接从 `https://<局域网IP>:5173/yohaku-dev.crt` 下载，启动时终端会打印这个地址。

- iPhone：用 Safari 下载后，到「设置 → 已下载描述文件」安装，再到「设置 → 通用 → 关于本机 → 证书信任设置」开启完全信任。
- Android：下载后到「设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书」，选择下载的 `yohaku-dev.crt`。

> 这张证书带有 CA 权限：信任它的手机会同时信任任何用 `key.pem` 签发的证书。私钥只留在本机，测试结束后从手机删除证书（iPhone：「设置 → 通用 → VPN 与设备管理」；Android：「加密与凭据 → 用户凭据」）。

### 构建后运行

```bash
npm run build
npm start
```

打开 [http://127.0.0.1:4317](http://127.0.0.1:4317)。默认仅允许本机访问。树莓派局域网 HTTPS 与开机启动配置见[树莓派部署](docs/raspberry-pi.md)。部署默认跳过完整测试，需要时使用 `bash scripts/pi-deploy.sh --test`。

### 添加到手机主屏幕

余白支持安装为 PWA：主屏幕显示「余白」和书本图标，安装后以独立窗口打开。手机必须信任站点的 HTTPS 证书，否则 Service Worker 无法注册，也无法完整安装；开发环境见[在手机上访问开发环境](#在手机上访问开发环境)，树莓派见[树莓派部署](docs/raspberry-pi.md)。

- iPhone：用 Safari 打开网站，选择「分享 → 添加到主屏幕」。
- Android：点页面底部的「安装」横幅，或在 Chrome 菜单中选择「安装应用」。

Service Worker 会缓存应用外壳，断网时仍能打开页面；账号、书架与 AI 功能仍需连接服务器，不提供离线资料缓存。

### 第一次阅读

1. 打开页面，创建首个网站账号；首个账号为管理员，朋友可通过邀请码注册。
2. 首个账号是网站拥有者，负责在「AI 设置」中连接 ChatGPT 订阅，或选择 iliad codix 保存 API key、测试并启用模型。所有网站账号共用这份授权和额度，其他账号无需单独配置。
3. 在「导入图片」选择书籍／文章并添加图片，支持 PNG、JPEG、WebP，单张最大 12 MB，每篇最多 100 张。全部显示「已上传」后点击「识别并注音」，提交后进入任务状态页；也可以直接导入文字。
4. 从「任务与导入草稿」继续上传未提交草稿或查看后台任务。正常任务不能手动暂停或删除；出错暂停后可重试未完成步骤、手动录入／注音或删除任务，成功结果继续保留。识别完成后点击「开始校对」，手动保存到新文章或原目标文章；新建书籍在采用结果时一起创建。保存成功后自动归档，可从任务页或导入页的「已归档」找回。
5. 点击「保存并阅读」后初始化分句；未分句的旧文章在载入阅读时也会自动初始化并保存，失败可手动重试。选中原文即可提问，点击已有问答标记可继续对应讨论。桌面点击「对话记录」，手机从底部把手上划可恢复上次对话；从面板顶部下滑收起，保留消息位置、筛选和未发送问题，等待回答也不会中断。本次页面会话内，阅读页与校对页共享按文章和问答组区分的草稿；刷新后清除。普通编辑保留句子边界，只有「重新分句」会再次请求模型划分。

### 使用 iliad codix

网站拥有者打开「AI 设置」，在「AI 提供方」选择 **iliad codix** 查看配置。选择只预览该提供方，点击「保存提供方」才生效。服务地址固定为 `https://iliad.codix.scw.eu/v1`，页面只读显示，后端也不接受修改；初始预设模型包含所给配置的七项。输入服务方的 API key，点击「保存 API 配置」；此操作不要求模型已通过测试，也不自动启用模型或发送推理请求。

保存后自动读取服务端 `/models`；可随时点「刷新模型列表」获取变化，embedding／autocomplete 模型不作为阅读助手候选。列表读取失败时保留预设或此前获取的选项，仍可手动填写模型 ID；列表提供的是服务端公布的候选，不表示它们已通过功能验证。

选择待测试模型，手动点「测试所选模型」，会发送三个小型请求检查流式文本、JSON 输出及图片输入，并显示各项结果和测试时间。三项通过后才可点「保存提供方」，一次启用 iliad codix 和所选模型，服务端同样拦截未测试或测试失败的模型。选择待测试项不切换正在使用的模型。测试记录保存在服务器，按密钥区分；更换密钥后需重新测试。重测可更新能力状态，明确不支持和暂时请求失败分别显示，失败不会自动认定模型不支持图片。已启用模型重测失败后停止用于新请求，需重新通过并保存；更换服务内容后可主动重新测试。

密钥仅保存在服务器的私有配置文件，不回显到网页；更新配置时留空继续使用已有密钥。选择「移除 API key」从本机移除密钥；服务方的密钥管理仍在对应服务完成。选择 OpenAI 后同样点击「保存提供方」，直接复用已有 ChatGPT 授权；切回 iliad codix 时保留已有 key、测试记录和已启用模型。

iliad codix 通过 Vercel AI SDK 的兼容接口提供识图、注音、分句和流式问答。图片识别和参考原图注音要求所选模型支持图片输入；识别、注音和分句使用 JSON 输出，并继续执行余白原有的正文与结果校验。模型名称和上下文／输出限制沿用提供的配置，实际可用性与能力以服务为准。此连接未接网页搜索，回答显示「未联网」；ChatGPT 连接仍使用原有的联网问答能力。

## 读音与识别

YOHAKU 将正文识别、生成注音和整批分句分成独立步骤，由服务端持久任务依次执行；每一步保存成功后再继续。某张失败仍继续处理其余图片，重试不重做已经保存成功的步骤；分句失败只补分句。服务器重启后可从未完成步骤恢复；中断且未保存的一次模型调用可能需要重做。注音阶段校验正文逐字一致，保留已有读音；优先参考原图清晰的印刷注音，缺失时结合语境推断，不确定时留空。新生成的读音统一标记为 `generated`，人工校对为 `manual`，历史资料中的原注音 `source` 继续保留。

阅读页会检查分句是否覆盖全部正文。尚未分句或只完成部分分句时，先显示等待条，完成后才显示正文和阅读操作；失败时保留正文，支持重试或进入校对。已完整分句的正文直接阅读，不重复调用模型。

整词读音用于保存和校对，阅读时仅在汉字部分显示对应假名。例如 `食べる → たべる` 只在「食」上方显示「た」，`お父さん → おとうさん` 只在「父」上方显示「とう」。

图片识别结果是待校对草稿，需核对错字、漏字、读序与特殊读法。整批识别失败也能保留原图、逐张手动录入并保存。任务正常处理时不能人工校对或注音；完成或出错暂停后可进入人工处理并固定结果，迟到结果不会覆盖手工文字。恢复后台后，旧校对页面无法保存，但编辑内容继续保留，须先手动复制留存；尚未保存的人工校对不提供跨设备协同编辑。只有出错暂停的任务允许删除，已保存文章保留。校对页可直接删除整篇文章；清空正文或移除最后一张图片后，也无需补文字就能删除文章。横排和竖排来源统一以横排阅读；当前新导入提取正文与读音，不还原原版布局，也不单独整理手写批注、页码或标题／列表结构。支持多张图片按顺序导入，双页照片不会自动拆成两页。

## 账号、AI 与数据

网站账号负责书架和资料归属，各账号的材料、原图和讨论独立保存。AI 由首个账号（网站拥有者）统一配置，所有已登录账号共用拥有者选定的授权和额度；其他账号不能连接、切换或断开 AI 授权，也看不到授权账户详情或 API 配置。目前支持 OpenAI 的 ChatGPT 订阅连接及 iliad codix 的 API key 连接；Claude 仍为禁用的预留项。

学习数据保存在运行应用的电脑上：

| 路径 | 内容 |
| --- | --- |
| `data/yohaku.sqlite` | 网站账号、导入草稿、后台图片任务及逐步结果、书籍、多图文章、HTML 正文、分句缓存与分组问答 |
| `data/images/` | 导入的图片及其保存版本 |
| `data/users/<ownerId>/providers/openai/` | 网站拥有者配置的共享 AI 授权与运行时数据 |
| `data/users/<ownerId>/providers/api_base/connection.json` | 网站拥有者的 API 地址、模型与密钥（文件权限 `600`，不纳入 Git） |
| `data/users/<ownerId>/providers/api_base/model-checks.json` | 按 API 配置区分的模型测试结果与时间，不包含密钥（文件权限 `600`） |

升级后复用拥有者已有的授权。其他账号旧的授权文件会保留，但不会再被用于 AI 请求。共享运行时一次执行一个 AI 步骤；后台批次轮转，问答与分句通过同一执行队列等待，避免整批图片长期占用。任务和已上传草稿默认保留，退出登录不会删除或取消。

`data/`、测试产物 `artifacts/` 和本地环境文件已被 Git 忽略。AI 识别、注音和问答需要联网，并将相应文字或图片发送给已连接的 AI 服务。划词问答只发送选区、涉及的完整句子及当前文章已有对话历史；网页搜索还会发送相关检索词。

## 开发与验证

技术栈：**React + Vite + Express + SQLite**。AI 提供方的认证和运行时与阅读、图片业务分离。

```bash
npm run check             # Node 测试与前端构建
npm run test:browser      # 阅读与校对浏览器回归
npm run test:browser:ai   # 账号、图片、书籍、划词问答与多图文章浏览器回归
npm run verify:stage3 -- --image=/绝对路径/测试原图.png  # 可选真实识图、分句和联网验证
npm run verify:image-tasks -- --image=/绝对路径/测试原图.png  # 可选真实任务、跨会话及重启恢复验证
npm run verify:api-base   # 配置 API key 后验证真实流式、分句、识图和注音；默认使用合成日语图片
```

浏览器测试默认使用 `/usr/bin/google-chrome`，可通过 `CHROME_PATH=/path/to/chrome` 指定路径。测试数据分别写入 `artifacts/e2e-data/` 和 `artifacts/ai-e2e-data/`。AI 浏览器回归使用明确的模型与 OAuth 替身，真实模型质量需另行实测。

| 目录 | 用途 |
| --- | --- |
| `client/` | 页面、阅读器、校对器与样式 |
| `server/` | HTTP API、账号、书籍与 SQLite 存储 |
| `server/providers/` | AI 提供方、授权与运行时适配 |
| `shared/` | 正文、注音与识别结果的处理和校验 |
| `tests/` | 数据、接口与浏览器验证 |
| `scripts/` | 开发启动、维护与验证命令 |
| `docs/` | 开发进度与后续计划 |

本地 OCR 的 MangaOCR／NDLOCR-Lite 实验代码保留供对照，相关专属测试已移除；当前图片任务使用识别、注音和整批分句的 LLM 流程，无需安装这些 Python 依赖。

后台图片任务沿用单服务进程与 SQLite，执行不依赖浏览器轮询。

## 开发进度

已完成能力、当前待办和后续阶段见[开发进度](docs/plan.md)。

正文以受控 HTML 为准，旧资料保留原 ID、整词振假名与识别记录，旧书页作为独立文章保留。JSON 导出包含完整正文结构；带来源、句子或问答标记的 Markdown 使用受控 HTML 保留引用。每篇对话只有手动删除后才重新建立，删除会同步清理正文问答标记。

使用 ChatGPT 提供方时，问答网页搜索使用网站拥有者同一份订阅授权，通过 OpenAI 原生 Responses 网页工具执行；识图、注音和分句继续由隔离的 Codex CLI 处理。该适配避免了当前 CLI 的网页检索兼容问题，不需要配置 API key。上述既有真实验证命令针对 ChatGPT 连接，只读取拥有者授权，不创建或修改网站文章，结果写入 Git 忽略的 `artifacts/stage3-live/`。
