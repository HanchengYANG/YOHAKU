# YOHAKU

**给喜欢的日语，留一点余白。**

YOHAKU（余白／よはく）是一个面向个人使用的日语阅读与学习工具。把书页照片、截图、歌词或文章放进自己的书架，借助 AI 识别正文、补全振假名，再对照原图校对、阅读和提问。

从一段想读的日语开始，一页一页积累自己的阅读材料。

## 可以做什么

- **导入图片和文字**：选择、粘贴或拖入照片与截图，也可以直接粘贴日语原文，保留段落和歌词分行。
- **一键识别并注音**：先识别、校正正文，再参考原图与语境生成读音。界面显示当前步骤和已用时间；注音失败时可单独重试，或先校对正文。
- **对照原图校对**：编辑正文与整词读音，联动高亮对应位置；按词查找后，全选或点选部分位置批量改音。支持原图放大、旋转及保存方向。
- **专注日语阅读**：振假名显示在汉字上方，可切换注音、调整字号。读音按完整词保存，显示时避免给正文中的假名重复注音。
- **整理书架与多页书籍**：保存独立材料，或逐页追加到同一本书；支持搜索、页面排序、上一页／下一页和选页。每页分别保留正文、读音、原图、识别记录与讨论。
- **围绕原文问 AI**：结合当前材料用中文解释词语、语法和句意，支持多轮追问与重新打开讨论。材料可导出为 JSON 或 Markdown。

## 开始使用

### 环境

- **Node.js 24**，项目使用 Node 内置 SQLite；`.nvmrc` 指定 `24.14.0`。
- 使用 AI 功能还需要 **Codex CLI** 和本人的 **ChatGPT 订阅授权**。当前运行时仅适配 CLI `0.160.1`，其他版本会拒绝启动 AI 请求；可通过 `YOHAKU_CODEX_PATH` 指定可执行文件。

### 本地开发

在项目根目录执行：

```bash
npm ci
npm run dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。前端由 Vite 提供，API 默认运行在 `127.0.0.1:4317`。

### 构建后运行

```bash
npm run build
npm start
```

打开 [http://127.0.0.1:4317](http://127.0.0.1:4317)。默认仅允许本机访问。树莓派局域网 HTTPS 与开机启动配置见[树莓派部署](docs/raspberry-pi.md)。

### 第一次阅读

1. 打开页面，创建首个网站账号；首个账号为管理员，朋友可通过邀请码注册。
2. 首个账号是网站拥有者，负责在「AI 设置」中连接 ChatGPT 订阅。所有网站账号共用这份授权和额度，其他账号无需单独配置。
3. 导入图片后点击「识别并注音」，或直接导入文字。图片支持 PNG、JPEG、WebP，单张最大 12 MB。
4. 对照原图校对正文和读音，选择保存为独立材料，或保存到已有／新建书籍。
5. 点击「保存并阅读」，之后可从书架重开、翻页或围绕材料提问。

## 读音与识别

YOHAKU 将正文识别与生成注音分成两个独立请求，一次点击后依次完成。注音阶段校验正文逐字一致，保留已有读音；优先参考原图清晰的印刷注音，缺失时结合语境推断，不确定时留空。新生成的读音统一标记为 `generated`，人工校对为 `manual`，历史资料中的原注音 `source` 继续保留。

整词读音用于保存和校对，阅读时仅在汉字部分显示对应假名。例如 `食べる → たべる` 只在「食」上方显示「た」，`お父さん → おとうさん` 只在「父」上方显示「とう」。

图片识别结果是待校对草稿，需核对错字、漏字、读序与特殊读法。横排和竖排来源统一以横排阅读；当前新导入提取正文与读音，不还原原版布局，也不单独整理手写批注、页码或标题／列表结构。每次导入一张图片，双页照片不会自动拆成两页。

## 账号、AI 与数据

网站账号负责书架和资料归属，各账号的材料、原图和讨论独立保存。AI 由首个账号（网站拥有者）统一配置，所有已登录账号共用拥有者选定的授权和额度；其他账号不能连接、切换或断开 AI 授权，也看不到授权账户详情。目前仅实现 OpenAI 的 ChatGPT 订阅连接，未接入按量收费 API key；Claude 和 API Base 仍为禁用的预留项。

学习数据保存在运行应用的电脑上：

| 路径 | 内容 |
| --- | --- |
| `data/yohaku.sqlite` | 网站账号、书籍、正文、读音、识别记录与讨论 |
| `data/images/` | 导入的图片及其保存版本 |
| `data/users/<ownerId>/providers/openai/` | 网站拥有者配置的共享 AI 授权与运行时数据 |

升级后复用拥有者已有的授权。其他账号旧的授权文件会保留，但不会再被用于 AI 请求。共享运行时一次处理一个任务，忙时请稍后重试。

`data/`、测试产物 `artifacts/` 和本地环境文件已被 Git 忽略。AI 识别、注音和讨论需要联网，并将相应文字或图片发送给已连接的 AI 服务。

## 开发与验证

技术栈：**React + Vite + Express + SQLite**。AI 提供方的认证和运行时与阅读、图片业务分离。

```bash
npm run check             # Node 测试与前端构建
npm run test:browser      # 阅读与校对浏览器回归
npm run test:browser:ai   # 账号、图片、书籍与讨论浏览器回归
```

浏览器测试默认使用 `/usr/bin/google-chrome`，可通过 `CHROME_PATH=/path/to/chrome` 指定路径。测试数据分别写入 `artifacts/e2e-data/` 和 `artifacts/ai-e2e-data/`。AI 浏览器回归使用明确的模型与 OAuth 替身，真实模型质量需另行实测。

| 目录 | 用途 |
| --- | --- |
| `client/` | 页面、阅读器、校对器与样式 |
| `server/` | HTTP API、账号、书籍与 SQLite 存储 |
| `server/providers/` | AI 提供方、授权与运行时适配 |
| `shared/` | 正文、注音与识别结果的处理和校验 |
| `tests/` | 数据、接口与浏览器验证 |
| `scripts/` | 开发启动、维护与验证命令 |
| `docs/` | 开发进度与后续计划 |

本地 OCR 的 MangaOCR／NDLOCR-Lite 实验代码保留供对照，当前图片导入固定使用两阶段 LLM 流程，无需安装这些 Python 依赖。
