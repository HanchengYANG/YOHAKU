# YOHAKU

**给喜欢的日语，留一点余白。**

YOHAKU（余白／よはく）是一个面向个人使用的日语阅读与学习工具。把书页照片、截图、歌词或文章放进自己的书架，借助 AI 识别正文、补全振假名，再对照原图校对、阅读和提问。

从一段想读的日语开始，一页一页积累自己的阅读材料。

## 可以做什么

- **统一导入**：上传照片、截图、扫描／文字 PDF、EPUB、UTF-8 文字，或粘贴原文与截图；本地猜测类型后确认。照片与截图一次导入一篇文章，多张图片按顺序组成该篇正文。PDF 成书先本地 OCR／提取全书文字，再由 AI 根据完整原文提议章节和非正文排除范围，按 PDF 实际页码修改、合并、拆分及排序后确认。逐页提取缓存可恢复和复用，未确认草稿可从导入入口继续。
- **按阅读进度准备**：正文校正后，分句与注音并行推进，组成约 1000 字阅读页；进度条显示当前阶段，当前页完成后自动显示，随后准备两页。已请求的阅读页或来源在离开、断网后继续准备，重启后续做；多篇文章独立运行，遵守各提供方的执行数量限制。旧图片任务继续按原流程完成。
- **跨设备接着上传**：选图后自动上传并保存导入草稿。A 设备传完一张后可退出，B 设备从「任务与导入草稿」继续添加图片、排序并提交；尚未传完的本地文件可重新选择或移除。任务以日期时间、书籍／标题或原文件名及短编号区分，侧栏固定显示「任务与导入草稿」入口。
- **按来源校对正文**：从阅读页定位图片、PDF 原页、EPUB 段落组或文字快照，编辑正文与读音。图片支持缩放、旋转和排序；保存会同步相关阅读页，保留原件、首次提取、AI 修改记录及问答快照。待核对状态独立于处理进度，可以先阅读再人工核对。
- **专注日语阅读**：振假名显示在汉字上方，可切换注音、调整字号。桌面书架可收起并记住选择，对话关闭后正文利用剩余宽度。读音按完整词保存，显示时避免给正文中的假名重复注音。
- **整理书籍与文章**：保存独立文章，或归入书籍；支持搜索、文章排序与上一篇／下一篇。一篇文章可追加多张照片，来源图、识别记录和正文位置互相对应。新导入确认类型后创建文章，按阅读需要准备正文；旧图片任务继续完成待校对草稿，手动保存后创建或追加文章。
- **划词问 AI**：选中原文即可翻译、解释语法或自定义提问；每轮只发送选区及所在句子，可联网核实并显示来源。一篇文章保留一条对话，按选区分组，编辑与重新分句后继续保留；删除原文关联的问答仍可查看、追问。

## 开始使用

### 环境

- **Node.js 24**，项目使用 Node 内置 SQLite；`.nvmrc` 指定 `24.14.0`。
- AI 可使用 **ChatGPT 订阅授权**，或连接 **iliad codix**。
- 使用 ChatGPT 订阅时需要 **Codex CLI**，当前运行时适配 CLI `0.160.1` 和 `0.163.0`，其他版本会拒绝启动 AI 请求；可通过 `YOHAKU_CODEX_PATH` 指定可执行文件。iliad codix 使用服务方的 API key，无需 Codex CLI 或 OpenCode。

### 本地开发

在项目根目录执行：

```bash
npm ci
bash scripts/install-document-runtime.sh
npm run dev
```

打开 [http://127.0.0.1:5173](http://127.0.0.1:5173)。前端由 Vite 提供，API 默认运行在 `127.0.0.1:4317`。`npm run dev` 会读取根目录的 `.env`（模板见 `.env.example`，命令行变量优先），局域网、HTTPS 等配置写进去后无需额外参数。

文档运行环境需要 Python 3.11+、venv 和 git。安装脚本在项目目录准备 PDF／EPUB 解析及 CPU 本地 OCR 依赖；可用 `DOCUMENT_PYTHON` 和 `NDLOCR_PYTHON` 指定已有环境。照片由 OCR 角色一次识别与校正；截图、扫描 PDF 先本地 OCR，再使用独立的 `correction` 角色校正。旧角色配置的校正选择初始复制 OCR，PDF 分章暂复用 OCR 角色。

### 在手机上访问开发环境

手机通过局域网访问时需要 HTTPS，Service Worker 和 PWA 安装都依赖它。直接执行：

```bash
npm run dev:https
```

脚本会自动探测本机局域网 IP、按需调用 `scripts/dev-tls.sh` 在 `~/.local/share/yohaku/dev/` 生成（或在 IP 变更时更新）自签证书，并启动 HTTPS 开发环境。若希望日常 `npm run dev` 默认启用，可 `cp .env.example .env` 并取消注释其中的局域网一节（`HOST=lan` 与 `TLS_*`）。

然后在手机上信任这张证书。第一次打开地址时浏览器会提示连接不安全，选择继续访问；页面底部会出现「下载证书」按钮。证书也可以直接从 `https://<局域网IP>:5173/yohaku-dev.crt` 下载，启动时终端会打印这个地址。

- iPhone：用 Safari 下载后，到「设置 → 已下载描述文件」安装，再到「设置 → 通用 → 关于本机 → 证书信任设置」开启完全信任。
- Android：下载后到「设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书」，选择下载的 `yohaku-dev.crt`。

> 这张证书带有 CA 权限：信任它的手机会同时信任任何用 `key.pem` 签发的证书。私钥只留在本机，测试结束后从手机删除证书（iPhone：「设置 → 通用 → VPN 与设备管理」；Android：「加密与凭据 → 用户凭据」）。

### 构建后运行

```bash
npm run build
npm start
```

打开 [http://127.0.0.1:4317](http://127.0.0.1:4317)。默认仅允许本机访问。树莓派局域网 HTTPS 与开机启动配置见[树莓派部署](docs/raspberry-pi.md)。部署默认跳过完整测试，需要时使用 `bash scripts/pi-deploy.sh --test`。

### 添加到手机主屏幕

余白支持安装为 PWA：主屏幕显示「余白」和书本图标，安装后以独立窗口打开。手机必须信任站点的 HTTPS 证书，否则 Service Worker 无法注册，也无法完整安装；开发环境见[在手机上访问开发环境](#在手机上访问开发环境)，树莓派见[树莓派部署](docs/raspberry-pi.md)。

- iPhone：用 Safari 打开网站，选择「分享 → 添加到主屏幕」。
- Android：点页面底部的「安装」横幅，或在 Chrome 菜单中选择「安装应用」。

Service Worker 会缓存应用外壳，断网时仍能打开页面；账号、书架与 AI 功能仍需连接服务器，不提供离线资料缓存。

### 第一次阅读

1. 打开页面，创建首个网站账号；首个账号为管理员，朋友可通过邀请码注册。
2. 首个账号是网站拥有者，负责在「AI 设置」中连接 ChatGPT 订阅或保存 iliad codix API key，再到「角色配置」分别选择 OCR、正文校正、注音、分句和问答的提供方与模型，点击保存时自动完成必要测试，通过后统一生效。所有网站账号共用这些连接和额度，其他账号无需单独配置。
3. 在「导入图片」选择书籍／文章并添加图片，支持 PNG、JPEG、WebP，单张最大 12 MB，每篇最多 100 张。全部显示「已上传」后点击「识别并注音」，提交后进入任务状态页；也可以直接导入文字。
4. 从「任务与导入草稿」继续上传未提交草稿或查看后台任务。正常任务不能手动暂停或删除；出错暂停后可重试未完成步骤、手动录入／注音或删除任务，成功结果继续保留。识别完成后点击「开始校对」，手动保存到新文章或原目标文章；新建书籍在采用结果时一起创建。保存成功后自动归档，可从任务页或导入页的「已归档」找回。
5. 点击「保存并阅读」后初始化分句；未分句的旧文章在载入阅读时也会自动初始化并保存，失败可手动重试。选中原文即可提问，点击已有问答标记可继续对应讨论。桌面点击「对话记录」，手机从底部把手上划可恢复上次对话；从面板顶部下滑收起，保留消息位置、筛选和未发送问题，等待回答也不会中断。本次页面会话内，阅读页与校对页共享按文章和问答组区分的草稿；刷新后清除。普通编辑保留句子边界，只有「重新分句」会再次请求模型划分。

### 连接管理与角色配置

「AI 设置」只管理连接。选择 OpenAI 可复用、连接或断开已经保存的 ChatGPT 订阅授权；选择 iliad codix 可输入并点击「保存 API key」。查看提供方不会改变业务配置，保存 key 不获取模型结果、不自动测试。服务地址固定为 `https://iliad.codix.scw.eu/v1`，前后端均不允许修改。密钥只保存在服务器私有配置文件，网页不回显；留空保存继续使用已有 key，「移除 API key」只移除本机保存的密钥。

网站拥有者在并列的「角色配置」页分别选择四个角色的提供方和具体模型。OpenAI 模型来自当前订阅目录，iliad codix 来自服务端 `/models`；每行显示提供方、模型与刷新目录，注音行可选择参考原图；推理选项收入默认折叠的「高级设置」。点击「保存角色配置」后自动测试各角色所需能力；同一次保存中，同一凭据、模型和推理设置的已通过能力可共用，避免重复调用。页面平时不展示测试结果，只有失败时在对应角色行说明未通过的能力和原因。

| 角色 | 必需能力 | 业务输入 |
| --- | --- | --- |
| OCR | 图片、JSON | 原图 |
| 注音 | JSON；开启「参考原图」后额外要求图片 | 正文和语境，可选原图 |
| 分句 | JSON | 正文 |
| 问答 | 流式文本 | 选区、句子和网站对话历史 |

每个角色独立保存推理设置。高级设置只展示当前模型目录明确提供的选项：推理强度、推理开关或 token 预算；没有支持记录的选项不显示。选择「模型默认」／「服务默认」时不额外发送对应参数；强度中的「关闭推理（none）」仅在目录支持时出现。OpenAI 使用当前 CLI 订阅目录提供的强度，iliad codix 使用已确认支持的模型选项，不把未确认的开关或预算套用到所有模型。切换提供方或模型会清除该行推理草稿；旧设置不再被当前目录支持时会明确提示，须调整或恢复服务默认后保存。

推理选项与角色一起原子保存，保存时按具体推理设置验证；相同模型的不同设置分别测试，不共用成功记录。未配置推理设置的已有角色继续使用服务默认。正在执行的调用保持其原有选项，后续步骤和重试读取最新角色设置。

「参考原图」默认关闭；开启后，没有原图的文章仍按文字注音。文本模型即使不支持图片，也可用于分句或纯文字注音。OpenAI 的 JSON 和图片能力通过 CLI 测试，问答通过实际 Responses 流式通道测试；iliad codix 通过兼容接口测试。选择角色和在连接页保存 key 不调用模型；点击「保存角色配置」才自动发起所需测试，每次保存都会重新验证当前凭据和所选模型。

选择好五个角色的连接和模型后即可点击整页唯一的「保存角色配置」。新增正文校正角色初始复制原 OCR 选择，PDF 分章暂用 OCR 角色。自动测试全部通过后一次生效；失败时保持原生效配置，显示对应角色和未通过的能力，可修改后重新保存。选择保持为草稿；`GET/PUT /api/ai/roles` 使用配置版本防止旧页面覆盖，并原子校验和保存。角色配置启用后，旧的全局提供方／模型切换接口会提示刷新页面。

升级保留已有授权、key 和测试记录，并把旧全局配置填入迁移草稿。首次完整保存前继续使用旧业务行为，浏览和选择不会自动测试。保存后每个步骤独立路由，授权、连接与队列仍按提供方共享，同一 key 可使用不同模型。某角色失效只阻塞对应步骤，沿用现有重试流程，不自动改用其他服务。

排队步骤在真正开始时解析最新角色配置；调用开始后固定本次提供方与模型，后续步骤和重试使用最新配置，已完成结果不重做。任务详情和问答记录显示实际使用的角色、提供方、模型及配置版本。问答切换账户、提供方或模型后创建新的远端会话，并继续保留和发送网站已有对话历史；切换配置不重算已完成分句，只有「重新分句」主动重算。

iliad codix 问答未接网页工具，界面标明「未联网」；OpenAI 继续使用网页工具。识别、注音和分句沿用原有正文与 JSON 结果校验。

## 读音与识别

新导入将提取、校正、分句和注音独立保存。照片一次完成 AI 识别与校正；截图和扫描 PDF 先本地 OCR，再 AI 校正；文字 PDF、EPUB、文字直接提取后校正。正文确定后分句与注音并行，组成约 1000 字阅读页并合并展示；当前页全部准备完成后自动显示，优先预取后两页。已请求的当前页或来源作为持久化任务，在退出、关页、断网后继续完成；后台任务范围限定于请求的阅读页或来源，多篇文章可以并行准备。每步可恢复和重试，不自动切换提供方；人工编辑后只补受影响的分句和注音。

新来源的注音先在本地完成，再由已配置的「注音」角色通读正文及候选读音，只返回改音、补音和无法确定的标识；正文校正仍由独立的「正文校正」角色先行完成。同一阅读页跨多个来源时合并查错，提供相邻语境；本地候选单独保存，AI 失败后重试直接复用。未明确指定推理强度时，查错优先使用模型目录声明支持的 `none`；明确设置的推理强度保持生效，失败不切换提供方。

注音阶段校验正文逐字一致，保护人工和原文读音、段落、分句、来源及当前问答标记。新生成的读音统一标记为 `generated`，人工校对为 `manual`，历史资料中的原注音 `source` 继续保留。旧图片任务和整篇编辑器继续使用原来的 AI 注音；在这些入口开启「参考原图」且存在原图时，额外参考印刷注音，不确定时留空。

来源校对保留正文编辑、注音校正、批量改音、撤销重做及预览。旧版整篇编辑器仍可点击「生成注音」，无需先创建图片草稿；结果先进入编辑器核对，保存后才更新文章。生成过程保留人工读音、段落、分句、来源和问答标记，正文逐字不变；只有实际发送过原图时，结果才标记为参考原图。

新来源阅读页同时检查完整分句与注音步骤。尚未全部完成时显示准备进度，完成后自动显示正文和阅读操作；失败时保留已保存的正文，支持重试或进入校对。再次打开时复用已完成步骤，不重复调用模型。

准备界面区分排队、执行中与失败，并显示当前来源、步骤和耗时。「处理详情」包含提供方、模型、处理编号及安全的错误类别、HTTP 状态或网络错误码；重试恢复后仍可查看本篇最近 5 次处理异常。诊断不会保存原始请求、响应、密钥或错误堆栈。

PDF 分批处理时，尚有后续来源的自动分句末尾先保留，下一批结合后文确认句界后再组成新阅读页。只重分尚未发布的尾句，已发布页位置和已有注音保持稳定；文章末尾即使没有句号，也会正常完成。

整词读音用于保存和校对，阅读时仅在汉字部分显示对应假名。例如 `食べる → たべる` 只在「食」上方显示「た」，`お父さん → おとうさん` 只在「父」上方显示「とう」。

新来源可以在提取失败时对照原件人工录入。进入编辑会冻结该来源的自动正文更新；迟到结果不会覆盖人工文字，其他来源可以继续处理。待核对／已核对与处理状态分开，人工核对不阻止阅读。旧图片任务继续原有草稿流程：完成或出错后人工校对、保存，成功步骤不重跑。尚未保存的人工修改不提供跨设备协同编辑。横排和竖排来源统一以横排阅读；当前提取正文与读音，不还原原版布局，也不单独整理手写批注、页码或标题／列表结构。支持多张图片按顺序组成一篇文章，双页照片不会自动拆成两页。

## 账号、AI 与数据

网站账号负责书架和资料归属，各账号的材料、原图和讨论独立保存。AI 由首个账号（网站拥有者）统一配置，所有已登录账号共用拥有者选定的授权和额度；其他账号不能连接、切换或断开 AI 授权，也看不到授权账户详情或 API 配置。目前支持 OpenAI 的 ChatGPT 订阅连接及 iliad codix 的 API key 连接；Claude 仍为禁用的预留项。

学习数据保存在运行应用的电脑上：

| 路径 | 内容 |
| --- | --- |
| `data/yohaku.sqlite` | 网站账号、角色配置、导入草稿、旧图片任务、书籍与文章、带版本来源片段、阅读页范围、处理步骤及分组问答；文章 HTML 为接口缓存 |
| `data/images/` | 导入的图片及其保存版本 |
| `data/imports/` | 不可变导入原文件；文字及 EPUB 原文快照另存于来源记录 |
| `data/users/<ownerId>/providers/openai/` | 网站拥有者配置的共享 AI 授权、当前授权下的能力测试记录与运行时数据 |
| `data/users/<ownerId>/providers/api_base/connection.json` | 网站拥有者的 API 地址、模型与密钥（文件权限 `600`，不纳入 Git） |
| `data/users/<ownerId>/providers/api_base/model-checks.json` | 按 API 凭据、模型及推理设置区分的能力测试结果与时间，不包含密钥（文件权限 `600`） |

升级后复用拥有者已有的授权。其他账号旧的授权文件会保留，但不会再被用于 AI 请求。各提供方的共享运行时分别限制执行数量；不同文章独立推进，本地提取和不同提供方的调用可以并行，同一提供方的问答与处理步骤共用队列。任务和已上传草稿默认保留，退出登录不会删除或取消。

`data/`、测试产物 `artifacts/` 和本地环境文件已被 Git 忽略。AI 识别、注音和问答需要联网，并将相应文字或图片发送给已连接的 AI 服务。划词问答只发送选区、涉及的完整句子及当前文章已有对话历史；网页搜索还会发送相关检索词。

## 开发与验证

技术栈：**React + Vite + Express + SQLite**。AI 提供方的认证和运行时与阅读、图片业务分离。

```bash
npm run check             # Node 测试与前端构建
npm run test:browser      # 阅读与校对浏览器回归

npm run verify:api-base   # 配置 API key 后验证真实流式、分句、识图和注音；默认使用合成日语图片
```

浏览器测试默认使用 `/usr/bin/google-chrome`，可通过 `CHROME_PATH=/path/to/chrome` 指定路径。测试数据分别写入 `artifacts/e2e-data/` 和 `artifacts/ai-e2e-data/`。AI 浏览器回归使用明确的模型与 OAuth 替身，真实模型质量需另行实测。 `npm run test:browser:ai` 先运行桌面项目，再为手机项目重新启动独立测试服务和数据库，避免两种设备的正常登录累计触发共享 IP 登录限流；生产权限与限流保持不变。结果分别写入 `artifacts/ai-browser-desktop/` 和 `artifacts/ai-browser-phone/`。

| `server/` | HTTP API、账号、书籍与 SQLite 存储 |

新来源的本地 OCR 使用 NDLOCR-Lite，日语注音使用 `pyopenjtalk-plus` 的词典、规则与 nani 模型，以及 Sudachi；运行时无需联网或 AI 授权。本地注音由独立的持久 Python 工作进程执行，与提供方队列分开。运行 `bash scripts/install-document-runtime.sh` 安装固定版本依赖；默认使用 `.venv-documents/bin/python`，可通过 `LOCAL_RUBY_PYTHON` 指定 Python。MangaOCR 等其他实验脚本保留供对照，不作为生产依赖。

正文以受控 HTML 为准，旧资料保留原 ID、整词振假名与识别记录，旧书页作为独立文章保留。JSON 导出包含完整正文结构；带来源、句子或问答标记的 Markdown 使用受控 HTML 保留引用。每篇对话只有手动删除后才重新建立，删除会同步清理正文问答标记。

使用 ChatGPT 提供方时，问答网页搜索使用网站拥有者同一份订阅授权，通过 OpenAI 原生 Responses 网页工具执行；识图、注音和分句继续由隔离的 Codex CLI 处理。该适配避免了当前 CLI 的网页检索兼容问题，不需要配置 API key。上述既有真实验证命令针对 ChatGPT 连接，只读取拥有者授权，不创建或修改网站文章，结果写入 Git 忽略的 `artifacts/stage3-live/`。

### 章节并发与后台任务

“任务与导入草稿”汇总图片批次、PDF／EPUB／文字导入，以及每篇文章的正文准备请求。任务详情保留来源页码、步骤、检查点和执行记录；本次请求的阅读范围及已启动的预取结束后自动归档，后续未访问内容按需建立新代次。运行或排队中的任务不能删除。已停止的失败或超时任务可重试失败步骤，或删除任务记录，原文、文章和预览仍保留。普通阅读心跳和重启不会恢复已删除任务，明确重新准备才创建新代次。

正文校对完成后，分句与注音独立执行，再将句子和读音合并到当前正文版本。不同章节共享有界资源池；当前章节优先，同级按文章轮转，连续三个前台任务后给后台任务一次机会。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `AI_HTTP_CONCURRENCY` | `4` | 每个提供方的 HTTP 并发数，同一章节最多占两个名额 |
| `OPENAI_CLI_WORKERS` | `2` | OpenAI CLI 工作进程数，同一章节最多占一个名额 |
| `LOCAL_OCR_WORKERS` | `1` | 共享本地 OCR 工作进程数 |
| `LOCAL_RUBY_WORKERS` | `1` | 本地注音工作进程数 |
| `LOCAL_PARSE_WORKERS` | `1` | 原始 PDF／EPUB 文件解析并发数，执行超时为 120 秒，排队另计 |
| `AI_EXECUTION_TIMEOUT_MS` | `180000` | 远端步骤实际执行超时，不含资源排队时间 |
| `AI_RATE_LIMIT_RETRIES` | `2` | HTTP 429 自动重试次数，退避等待不占执行名额 |
| `AI_RATE_LIMIT_BACKOFF_MS` | `1000` | HTTP 429 初始退避毫秒数，指数递增至最多 30 秒 |

OpenAI CLI 的第一个工作进程沿用原运行目录；旧会话默认回到该进程，新会话的工作进程归属持久化。统一任务接口为 `GET /api/tasks`、`GET /api/tasks/:id`、`POST /api/tasks/:id/retry`、`DELETE /api/tasks/:id`，变更操作携带当前任务 `version`。
